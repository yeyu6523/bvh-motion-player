## 11 个原始 BVH

测试文件为 008b、012、035、041、057、073、076、KICK R、walk1、walk2、walk3。涉及 18/27 个有效关节、57/84 个通道，312–8531 帧。

对每个文件保存 SHA256，首帧、中间帧与接近末帧使用独立的 Three.js BVHLoader/AnimationMixer 对照关节世界坐标，末帧还做有限数值检查。全部文件的最大位置差异不超过 **0.000095 个源文件单位**（参考实现使用 Float32 动画轨道）。原始课程文件只读取，不修改、不上传。

## 桌面交互验证

- 真实窗口读入并绘制内置示例；没有网络服务器，使用 `file:` 页面和打包 Worker。
- 点击播放后帧数增加，点击暂停并等待后帧数不变。
- 同一约 420 ms 时间窗内，0.5× 前进约 12 帧，2× 前进约 51 帧；精确比例由纯时钟单元测试校验，界面测试允许计时调度差异。
- 比较视图区像素，确认不同帧的骨架实际变化，而不只是进度数字变化。
- Space 播放/暂停、上一帧、下一帧、指定帧 seek、关闭循环到末帧停止、重新播放和循环均通过。
- 文件输入与拖放以真实 DOM File / DataTransfer 事件驱动，11 个 BVH 均可加载；无效文件不替换已载入片段。
- 完整尺寸与 960×720 小窗口均截图检查，并断言播放按钮、速度选择和时间轴完全位于窗口内部。
- 向上轴、重置视角、网格、标记和跟随开关经过调用验证；这些显示选项没有逐一做像素断言。

## 已修复的问题

1. 隐藏测试窗口触发应用“后台暂停”，导致首次播放测试失败；改为真实可见窗口测试，不删除正式的后台暂停行为。
2. 浮点除法可能使部分 60 fps 的精确 seek 少一帧；加入微小的帧索引容差，并对 240 个位置逐一断言。
3. canvas 内在尺寸引起小窗口 grid 无法收缩，播放控件被裁切；将 canvas 设为绝对定位，补充子容器 min-height 与控件边界断言，重新截图通过。
4. 构建依赖 minimatch 的旧版有审计告警；使用统一 override 后重新安装和打包验证，完整 audit 为 0。

## 诚实的验证边界

- 不宣称在所有 BVH 方言、所有显卡、所有 Windows 版本上测试过。
- 本机测试未人工点选系统原生打开对话框；对话框/IPC 路径经代码检查，读取、解析及播放经本地文件输入和拖放测试。
- 骨架归一化与地面对齐不代表动作重定向或脚部 IK。
- Vite 对单个约 576 kB 的本地渲染 JS 提示 chunk 大小告警，不是构建错误；桌面离线使用无远程下载要求。
- EXE 未购买代码签名证书，分发时说明未知发布者提示，不冒充已签名软件。
